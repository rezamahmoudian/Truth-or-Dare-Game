# جرئت یا حقیقت — Truth or Dare

بازی اجتماعی چندنفره‌ی آنلاین: آشنایی با یک بازی رندوم شروع می‌شود، با دوستی و
چت ادامه پیدا می‌کند، و هر وقت خواستند دوباره وسط چت بازی راه می‌اندازند.

**وضعیت: فاز ۷ — PWA و آماده‌ی انتشار.** راهنمای استقرار: [`DEPLOY.md`](DEPLOY.md)

```
غریبه → صف → روم → چت → «شروع بازی» → درخواست دوستی
   → چت خصوصی → بازی دوباره وسط همان چت
```

## ایمنی

**فیلتر کلمات** — سخت‌ترین بخشش فارسی است، نه مدل.

- `ي` عربی و `ی` فارسی، `ك` و `ک`، ZWNJ، اعراب و کشیده همه یکی شمرده می‌شوند
- `کثاااافت`، `ک ث ا ف ت` و `ک.ث.ا.ف.ت` همگی گرفته می‌شوند
- **مرزبندی کلمه پیش‌فرض روشن است** — وگرنه `کس` داخل `عکس` و `هرکسی` گیر
  می‌افتد و فیلتری که روی کلمات معمولی شلیک کند، توسط اپراتور خاموش می‌شود
- **پسوندهای فارسی** (`ی`، `ها`، `ش`، `تون`…) برای کلمات ۴ حرف به بالا پذیرفته
  می‌شوند: `احمقی` گرفته می‌شود ولی `کسی` نه
- دو سطح: **پوشاندن** (`***`) برای زننده‌ها و **رد کردن** برای بدترین‌ها. فیلتری
  که فقط رد کند، آدم را وادار می‌کند دوباره و عصبانی‌تر بنویسد

کلمات در دیتابیس‌اند و از پنل ادمین قابل ویرایش‌اند — لیست هیچ‌وقت کامل نمی‌شود.

**گزارش و بلاک**

- گزارش **هرگز خودکار اعمال نمی‌شود**؛ بن خودکار بعد از N گزارش، سلاحی است در
  دست هر کسی که سه تا دوست داشته باشد
- گزارش روی پیامی که در گفتگویش نبوده‌اید، رد می‌شود
- **بلاک، دوستی را هم حذف می‌کند** — وگرنه طرف در لیست دوستان می‌ماند و چت
  خصوصی از سمت او زنده است
- حذف پیام **نرم** است: گزارشی که به آن اشاره دارد باید فردا برای مدیر خوانا باشد
- بن = `is_active=False`؛ هم REST و هم WebSocket توکن موجود را رد می‌کنند

```bash
docker compose exec -T backend python manage.py seed_banned_words
```

## دوستی

یک ردیف به ازای هر جفت، نه دو ردیف آینه‌ای — دوستی متقارن است و دو ردیف یعنی
دو جا برای ناهماهنگ شدن. جهت فقط برای این نگه داشته می‌شود که معلوم شود دکمه‌ی
«قبول» را چه کسی می‌بیند.

- **قبول کردن، چت خصوصی را می‌سازد** (idempotent — قبول از دو دستگاه، دو
  گفتگو نمی‌سازد) و یک پیام سیستمی در آن می‌گذارد؛ چت خصوصی خالی بین دو نفری
  که یک‌بار حرف زده‌اند، شروع کردنش سخت است
- **درخواست متقابل = قبول**، نه درخواست دوم
- **حذف دوستی، تاریخچه را پاک نمی‌کند** — پیام‌ها مال هر دو نفرند
- کسی که بلاک کرده یا بلاک شده، قابل افزودن نیست
- درخواست دوستی از **شیت بازیکن‌ها** در هدر روم فرستاده می‌شود: همان لحظه‌ای که
  بازی تمام شده و یادت هست چه کسی جالب بود

## حذف گفتگو

حذف **برای هر نفر جداگانه** است. طرف مقابل روم و تمام پیام‌هایش را نگه می‌دارد —
حذفی که به تاریخچه‌ی دیگری دست بزند، راهی برای پاک کردن شواهد است نه مرتب کردن.

- پیام‌های تا لحظه‌ی حذف برای حذف‌کننده پنهان می‌شوند
- اگر پیام جدیدی بیاید، گفتگو برمی‌گردد و فقط پیام‌های بعد از حذف را نشان می‌دهد
- حذف یک **روم** یعنی خروج از آن هم؛ حذف یک **چت خصوصی** فقط پنهان می‌کند، تا
  طرف مقابل هنوز بتواند به شما برسد

## عمر روم

روم تا وقتی صاحبش آن را نبندد باز می‌ماند — نه با خروج همه. دلیلش این است که
دو نفری که خوب گرم گرفته‌اند ولی هنوز درخواست دوستی نداده‌اند، با بستن تب
همدیگر را برای همیشه از دست نمی‌دهند.

- صاحب روم = سازنده‌اش، یا در روم‌های matchmaking، بازیکنی که بیشتر از همه صبر
  کرده
- اگر صاحب روم خارج شود، مالکیت به قدیمی‌ترین عضو باقی‌مانده می‌رسد — وگرنه
  دکمه‌ی بستن صاحب ندارد و روم هرگز بسته نمی‌شود
- روم بسته تاریخچه‌اش را نگه می‌دارد ولی پیام جدید نمی‌پذیرد و کسی نمی‌تواند
  واردش شود

## Matchmaking

تطبیق در **یک جا** انجام می‌شود: یک تسک Celery که هر ۲ ثانیه اجرا می‌شود و زیر
یک قفل Redis است. اگر هر کلاینت خودش تطبیق می‌داد، دو نفر می‌توانستند همزمان
در دو روم مختلف قرار بگیرند.

- **حالت‌ها دیتا هستند** (`MatchMode`) — حالت جدید یک رکورد است، نه انتشار APK
- **بعد از ۲۰ ثانیه شرط‌ها شل می‌شوند** و به کاربر گفته می‌شود
- **«بازی با دختر» و «بازی با پسر» یک تطبیق‌اند از دو طرف** — جنسیت روی تیکت
  است نه روی صف
- **طرف کم‌عرضه در صف اولویت دارد** و حالت‌های جنسیتی سهمیه روزانه دارند؛ وگرنه
  صف پرتقاضا گرسنه می‌ماند و کاربر تازه فکر می‌کند اپ مرده است
- بلاک‌شده‌ها و حریف‌های اخیر فیلتر می‌شوند
- تیکت بعد از ۳ دقیقه منقضی می‌شود با **پیشنهاد مشخص**، نه چرخش بی‌پایان
- **روم بدون بازی باز می‌شود** — اول با هم حرف می‌زنند، بعد صاحب روم هر وقت
  خواست بازی را شروع می‌کند

```bash
docker compose exec -T backend python manage.py seed_match_modes
```

## موتور بازی

**هیچ تایمری در کار نیست.** نوبت منتظر آدم می‌ماند، نه ساعت. یک روم می‌تواند
یک ساعت روی یک نوبت بماند در حالی که بازیکن‌ها درباره‌ی چیز دیگری حرف می‌زنند و
بعد ادامه بدهند.

```
CHOOSING ──انتخاب──▶ ANSWERING ──پاسخ──▶ CONFIRMING ──تأیید──▶ نوبت بعد
    │                     │                    │
    └──رد کردن نوبت───────┴────────────────────┴──▶ نوبت بعد
                          │
          صاحب روم از هر مرحله‌ای می‌تواند جلو ببرد
```

- **بازی خودکار شروع نمی‌شود** — حتی وقتی matchmaking دو غریبه را به هم وصل
  می‌کند. اول حرف می‌زنند؛ صاحب روم هر وقت خواست شروع می‌کند.
- **کی می‌تواند نوبت را جلو ببرد:** در بازی دونفره، طرف مقابل (و بعد نوبت خودش
  می‌شود). در چندنفره، بیش از نصفِ همه به‌جز پاسخ‌دهنده. و **صاحب روم به‌تنهایی،
  در هر لحظه، با جواب یا بی‌جواب.**
- پس همیشه کسی هست که بتواند بازی را از گیر دربیاورد. اگر صاحب روم برود،
  مالکیت به قدیمی‌ترین عضو می‌رسد؛ دکمه هیچ‌وقت بی‌صاحب نمی‌شود.
- **سرور تنها مرجع نوبت است.** کلاینت فقط snapshot دریافتی را رندر می‌کند.
- **رویدادهای بازی پیام‌اند.** سؤال و جواب در همان جریان چت‌اند، نه در پنلی
  کنار آن.

سوکت به‌جای رویدادهای جداگانه، روی هر تغییر یک **snapshot کامل** (`game.state`)
می‌فرستد: idempotent است و بعد از قطعی اتصال فقط آخرینش لازم است.

```bash
docker compose exec -T backend python manage.py seed_prompts
```

## WebSocket

یک سوکت برای کل اپ: `ws://<host>/ws/`

احراز هویت با زیرپروتکل `["ft.jwt", <access-token>]` — نه query string، چون
توکن زنده است و query در لاگ پراکسی می‌نشیند.

```
کلاینت → سرور   conv.subscribe · conv.unsubscribe · chat.send
                 chat.typing · chat.read · chat.react · ping
سرور → کلاینت   ready · chat.message · conv.updated · chat.typing
                 chat.read · chat.reaction · presence · error · pong
```

گروه‌ها: `user.<id>` برای رویدادهای ماندگار (پیام، به‌روزرسانی لیست) و
`conv.<uuid>` فقط برای ترافیک گذرا (تایپینگ، حضور).

تست دود سرتاسری با دو کاربر و دو سوکت واقعی:

```bash
docker compose exec -T backend python scripts/smoke_chat.py
```

```bash
docker compose exec -T backend python scripts/smoke_game.py
```

```bash
docker compose exec -T backend python scripts/smoke_match.py
```

```bash
docker compose exec -T backend python scripts/smoke_social.py
```

```bash
docker compose exec -T backend python scripts/smoke_moderation.py
```

> **دو نکته عملیاتی که وقت می‌گیرند اگر ندانید:**
> `docker compose restart` متغیرهای `env_file` را دوباره نمی‌خواند — برای تغییر
> `.env` باید `docker compose up -d <service>` زد. و ورکر Celery کد را
> hot-reload نمی‌کند؛ بعد از اضافه کردن تسک جدید حتماً
> `docker compose restart worker` لازم است، وگرنه تسک
> «unregistered» رد می‌شود.

قوانینی که سمت سرور اجبار می‌شوند: دروازه‌ی سنی (`MIN_AGE`)، **تاریخ تولد
نوشتنی‌فقط‌یک‌بار** (گیت سنی که قابل ویرایش باشد گیت نیست)، و سقف تغییر جنسیت
(`MAX_GENDER_CHANGES`).

## نکات معماری که در همین فاز اعمال شده‌اند

- **Same-origin بودن `/api` و `/ws`** — در توسعه Vite پراکسی می‌کند و در
  پروداکشن Caddy. نتیجه‌اش این است که هیچ‌وقت CORS و هیچ «آدرس پایه‌ی API» به
  ازای محیط‌های مختلف وجود ندارد.
- **مدل کاربر سفارشی از همین اولین مایگریشن** — عوض کردن `AUTH_USER_MODEL` بعد
  از ساخته شدن جدول‌ها یکی از دردناک‌ترین مایگریشن‌های جنگو است. فعلاً خالی است؛
  فاز ۱ پرش می‌کند.
- **`BigAutoField` به‌عنوان پیش‌فرض** — شناسه‌ی پیام‌ها باید bigint باشد تا
  شمارش پیام‌های خوانده‌نشده و صفحه‌بندی به یک مقایسه‌ی عددی ساده تبدیل شود.
- **لاگ JSON با `ensure_ascii=False`** — لاگ‌ها متن فارسی دارند.
- **`100dvh` و `env(safe-area-inset-*)`** در اسکلت UI.
- **`beat` جدا از `worker`** — تایمرهای نوبت زمان‌بندی‌شده‌اند، و اجرای beat
  داخل ورکر یعنی زمان‌بندی تکراری به‌محض اینکه ورکر دوم بالا بیاید.

قواعد کامل معماری در `.claude/skills/truth-dare-architecture/SKILL.md` است.

## PWA

- **service worker فقط پوسته را کش می‌کند** (HTML، JS، CSS، فونت، آیکون) تا اپ
  فوراً و حتی با اینترنت ضعیف باز شود
- **`/api` هرگز کش نمی‌شود.** چت و بازی زنده‌اند؛ جواب کهنه بدتر از خطاست — نوبت
  اشتباه یا پیام حذف‌شده را نشان می‌دهد و کسی نمی‌فهمد کهنه است
- به‌روزرسانی **پیشنهاد می‌شود، تحمیل نمی‌شود** — اپ وسط تایپ کردن کسی ری‌لود
  نمی‌کند
- `sw.js` و `index.html` با `Cache-Control: no-cache` سرو می‌شوند؛ وگرنه اپ نصب‌شده
  هیچ‌وقت نسخه‌ی جدید را نمی‌بیند
- بنر نصب **روی صفحه‌ی اصلی**، نه موقع باز شدن اپ؛ و بعد از رد کردن تا یک هفته
  دوباره نمی‌آید. iOS رویداد نصب ندارد، پس مراحل دستی را نشان می‌دهد
- آیکون‌ها نشان چهارپر از خود طراحی‌اند؛ نسخه‌ی `maskable` داخل دایره‌ی امن است تا
  لانچر اندروید نوک‌هایش را نبُرد

### چرا Web Push نداریم

در رودمپ «اختیاری» بود و آگاهانه انجام نشد.

Web Push روی کروم و اندروید از سرورهای **FCM گوگل** رد می‌شود، و این سرورها
برای کاربر ایرانی قابل اتکا نیستند. نتیجه‌اش بدترین حالت ممکن است: اعلانی که
گاهی می‌رسد و گاهی نه، بدون اینکه کاربر یا ما بفهمیم کدام. کسی که منتظر نوبتش
است و اعلان نمی‌گیرد، فکر می‌کند بازی خراب است.

به‌جایش اپ طوری ساخته شده که **بدون اعلان هم کامل کار کند**: هیچ نوبتی تایمر
ندارد و منقضی نمی‌شود، پس هیچ‌کس با دیر باز کردن اپ چیزی را از دست نمی‌دهد —
تعداد پیام‌های نخوانده و وضعیت نوبت هر وقت برگردد سر جایش است.

اگر روزی لازم شد، جای درستش اعلان داخل خود APK است (نه Web Push مرورگر) با یک
ارائه‌دهنده‌ی داخلی مثل پوش‌ه یا نجوا.

## طراحی

تم تیره‌ی تک‌حالته بر پایه‌ی فایل طراحی، فارسی و RTL، با فونت **Vazirmatn** که
داخل مخزن است (نه از CDN — گوگل فونتس برای کاربر ایرانی قابل اتکا نیست).

پالت از خود فایل طراحی نمونه‌برداری شده: پایه‌ی بنفشِ عمیق `#1a0a2d`، برند
صورتی‌قرمز `#ff4d6d`، و هیروی گرم نارنجی→قرمز. هر حالت بازی یک `--tint` دارد که
کاشی آیکون، خود آیکون و نقطه‌ی وضعیتش از همان می‌آید.

**اعدادی که در UI دیده می‌شوند واقعی‌اند** — نه تزئین:

- `queue_size` و `queue_state` از صف واقعی می‌آیند؛ نقطه‌ی سبز روی صف خالی،
  دروغی است که کاربر سی ثانیه بعد می‌فهمد
- «`n` نفر الان آنلاین» و ردیف «فعال الان» از `last_seen_at` می‌آیند
- **streak** روزهای متوالیِ بازی‌کردن را می‌شمارد (`User.streak_days`) و اگر صفر
  باشد اصلاً نمایش داده نمی‌شود

`GET /api/lobby/` همه‌ی این‌ها را در **یک درخواست** برمی‌گرداند — صفحه‌ی اصلی
چهار تا کال نمی‌زند.

- **عمق از لبه‌ی روشنِ بالا می‌آید، نه از سایه.** سایه روی پس‌زمینه‌ی نزدیک به
  سیاه تقریباً دیده نمی‌شود و فقط رنگ را گل‌آلود می‌کند.
- خنثی‌ها یک رگه بنفش دارند؛ خاکستری کاملاً خنثی روی OLED مرده به‌نظر می‌رسد.
- **ارتفاع خط ۱٫۷۵** — فارسی در ۱٫۵ نقطه‌های زیر «ب/پ/ج» با خط بعدی برخورد
  می‌کنند.
- فلش بازگشت SVG است نه کاراکتر: `›` در RTL توسط یونیکد آینه می‌شود و
  برعکس نشان می‌دهد.
- در چت: **گروه‌بندی پیام‌های پشت‌سرهم**، ساعت زیر هر پیام، جداکننده‌ی روز با
  تاریخ شمسی، و گوشه‌ی نزدیک به گوینده تیزتر از بقیه.
- `prefers-reduced-motion` رعایت می‌شود.

## دستورات مفید

```bash
docker compose exec backend python manage.py makemigrations
docker compose exec backend ruff check .
docker compose exec frontend npm run lint
docker compose logs -f backend
docker compose down -v          # پاک کردن کامل دیتابیس
```

اندازه‌گیری (هر دو کاربر و دیتای واقعی می‌سازند — روی پروداکشن اجرا نکنید):

```bash
docker compose exec backend python scripts/profile_queries.py
```

```bash
docker compose exec backend python scripts/loadtest_ws.py --idle 200 --rooms 8
```

اولی هر صفحه را با دو حجم داده اجرا می‌کند و می‌گوید کدام کوئری با بزرگ شدن
داده رشد می‌کند. دومی تأخیر رسیدن پیام را وقتی چند روم همزمان حرف می‌زنند
می‌سنجد؛ عدد اندازه‌گیری‌شده و رابطه‌اش با تعداد worker در `DEPLOY.md` است.
